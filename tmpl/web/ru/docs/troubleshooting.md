# Проверьте исходник, затем оформление

Если публикация возвращает 404, начните с запрошенного представления. Не рассчитывайте на подстановку другого языка.

## Нет локализованного HTML

1. Проверьте путь страницы и поддерживаемую локаль. Укажите `.html` для явного запроса HTML: адрес без расширения может выбрать Markdown для клиента, который его поддерживает.
2. Проверьте точный исходник: `/ru/features.html` требует `tmpl/web/ru/features.md`.
3. Проверьте непустые `title` и `description`, календарную дату `date` в формате ISO и доступность Markdown.
4. Убедитесь, что настроенный шаблон существует, читается и не пуст. При сбое рендеринга проверьте его синтаксис.

Движок не заменяет отсутствующий HTML другим языком. Изучайте диагностику локального сервера, не раскрывая закрытую конфигурацию и сообщения.

## Нет нейтрального Markdown

Проверьте сначала корректный исходник без локали в `tmpl/web/`, затем английский, затем исходник локали по умолчанию. Одного файла на другом языке недостаточно. Используйте `/features.md` для нейтрального Markdown или `/ru/features.md` для точного русского исходника.

## Файлы обнаружения устарели

Проверьте, что `cms:generate` использует те же правила публикации и локали, что сервер. После изменения контента обновите файлы. Доступность HTML и нейтрального исходника проверяются отдельно.

## В переключателе нет языка

Переключатель показывает доступные HTML-варианты. Проверьте соответствующий исходник и шаблон, прежде чем добавлять ссылку на отсутствующий маршрут.

Если нужна помощь, [пришлите маршрут, симптомы и диагностику без секретов](/ru/contacts).
