# Для каждой аудитории — свой исходник

Я веду языковые версии как авторский контент в Git. Внешний агент может помочь адаптировать формулировки, а CMS публикует подготовленные файлы. Она не вызывает API перевода и не запускает задания локализации.

## Практический порядок

1. Определите назначение страницы, факты, ссылки и аудиторию.
2. Подготовьте Markdown-файл с тем же маршрутом в каждой целевой локали.
3. Проверьте язык, метаданные, контакты и внутренние ссылки. Адаптируйте подачу, сохраняя смысл.
4. Перед публикацией посмотрите обе страницы и переключатель языка.
5. После изменения набора публикаций обновите файлы обнаружения.

На этом сайте русский — исходный язык. Английская версия сохраняет назначение страниц; решение о выполнении локализации принимает владелец.

## Что должно совпадать

Пути страниц, факты о продукте, контакты и смысл призывов к действию. Внутренние ссылки сохраняют активную локаль. У каждого файла нужны непустые `title` и `description`, а также календарная дата `date` в формате ISO.
