# Markdown в основе. HTML для читателя.

Я строю TeqCMS вокруг простой идеи: исходный контент должен быть понятным и проверяемым, а каждый читатель должен получать удобное представление.

## Файлы, которыми вы распоряжаетесь

Контент хранится в Markdown, оформление — в общих шаблонах. Можно работать в своём редакторе, изучать репозиторий и вести историю изменений в Git. Для публикации контента не нужны база CMS и административная панель.

## Один материал, отдельные языковые версии

У каждого языка свой файл с одинаковым относительным путём в каталоге локали. Русская и английская страницы могут использовать общее оформление и разные формулировки для своих аудиторий. Для HTML нужен исходник именно запрошенного языка; отсутствие перевода даёт 404.

## HTML для людей, Markdown для агентов

TeqCMS публикует два представления по разным URL:

| Откройте пример | Что получите |
| --- | --- |
| [Русская страница](/ru/v2/features) | HTML из русского исходника |
| [Английская страница](/en/v2/features) | HTML из английского исходника |
| [Открытый Markdown](/v2/features) | Авторский исходник вместе с метаданными |

Нейтральный Markdown URL выбирает английский исходник, затем исходник локали по умолчанию. Представление задаёт URL, независимо от того, кто запрашивает ресурс — браузер или агент.

## Общие шаблоны и серверный рендеринг

Приложение выбирает шаблонизатор и задаёт шаблоны представления. На этом сайте я использую Nunjucks. Общий макет поддерживает единые навигацию, метаданные и оформление, а TeqCMS превращает Markdown в HTML на сервере.

## Агент работает с теми же файлами

Внешнему агенту можно поручить написание, адаптацию и проверку текстов. Перед публикацией я просматриваю результат и разницу версий. TeqCMS отдаёт подготовленные исходники; при запросе страницы она не запускает агента и не вызывает API перевода.

## Файлы обнаружения из публичных материалов

Команда движка `cms:generate` умеет формировать `robots.txt`, `llms.txt` и `sitemap.xml` по настроенным публичным публикациям. Владелец сайта обновляет их после правок контента. Закрытые инструкции не входят в набор публичных материалов.

## Для каких задач подходит

Я использую этот подход для промосайтов. Он также подходит для документации, порталов разработчиков и многоязычных сайтов проектов, которые ведутся через файлы и Git. Если редакторам нужен визуальный интерфейс, сначала оцените, как они будут работать с контентом.
